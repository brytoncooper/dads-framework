# create-dads invariants

- INV-CREATE-DADS-1: Invalid creation arguments are rejected before any project file is written. — enforced by `src/create-dads.ts#createDads`, which parses arguments before calling `initializeDadsProject`; proven by `src/create-dads.test.ts` "rejects unknown options and extra positional arguments before writing" and "rejects retired recipe options before writing".
- INV-CREATE-DADS-4: Repeating initialization after a successful install creates no new project files and does not install dependencies again. — enforced by `src/create-dads.ts#createDads` and its `dependenciesAreInstalled` guard; proven by `src/create-dads.test.ts` "installs once, then leaves the same project unchanged".
- INV-CREATE-DADS-5: A failed installation leaves the created project files intact and stays pending, so the next ordinary run installs again; the installation is recorded only after it succeeds. — enforced by `src/create-dads.ts#createDads`, where `recordDadsDependencyInstallation` runs only after the awaited `installDependencies` resolves; proven by `src/create-dads.test.ts` "retries a failed dependency installation without rewriting project files".
- INV-CREATE-DADS-6: `--skip-install` writes project files without running an installation. — enforced by the `installed` condition in `src/create-dads.ts#createDads`; proven by `src/create-dads.test.ts` "creates the named APIs and their modern dependencies".
- INV-CREATE-DADS-7: `--existing` writes an isolated `dads/` project and leaves the host application's files unchanged. — enforced by `src/create-dads.ts#createDads` passing the parsed mode to `deriveDadsProjectName` and `initializeDadsProject`; proven by `src/create-dads.test.ts` "adds an isolated project to an existing app".
- INV-CREATE-DADS-10: `--dry-run` reports the owned files without writing them and without running an installation. — enforced by the `dryRun` flag `src/create-dads.ts#createDads` passes to `initializeDadsProject` and by the `!request.dryRun` term of its `installed` condition; proven by `src/create-dads.test.ts` "runs no installation for a dry run" and `src/cli.test.ts` "runs no installation and writes no project file for --dry-run".
- INV-CREATE-DADS-11: The executable reports a success as one `{"ok":true,…}` line on standard output and exits 0. — enforced by the success branch of `src/cli.ts`; proven by `src/cli.test.ts` "prints an ok envelope on standard output for a successful --json run".
- INV-CREATE-DADS-12: A failure is written to standard error and exits nonzero — `{"ok":false,"error":…}` under `--json`, `Dads: <message>` without it — leaving standard output empty. — enforced by the catch block of `src/cli.ts`, which writes to `process.stderr` and sets `process.exitCode = 1`; proven by `src/cli.test.ts` "exits nonzero and writes the failure to standard error without --json" and "carries installation diagnostics inside the --json error instead of standard output".
- INV-CREATE-DADS-13: Under `--json` the installation's own output is captured rather than inherited, and a failed installation's diagnostics travel inside the structured error instead of contaminating standard output. — enforced by `src/cli.ts#runNpm`, which pipes the child's streams under `--json` and joins them into the rejection message; proven by `src/cli.test.ts` "carries installation diagnostics inside the --json error instead of standard output".
- INV-CREATE-DADS-14: An existing project is diagnosed and the report written out before any project file exists, and a target with no project in it is not diagnosed at all. — enforced by `src/create-dads.ts#createDads`, which awaits `#diagnoseBeforeCreating` before `initializeDadsProject`, and by `#classifyTarget`, which recognizes a project on the same rule `initializeDadsProject` does; proven by `src/create-dads.test.ts` "diagnoses an existing project before it writes, and creates the same files either way", which asserts the project root does not exist at the moment the report is written, "says so in one line and reads nothing when the target is fresh", and `src/cli.test.ts` "prints the doctor's report over an existing application before it is ready".
- INV-CREATE-DADS-15: The diagnosis never changes what is created: a run that skips the doctor writes the same files as one that ran it. — enforced by `src/create-dads.ts#diagnoseBeforeCreating`, whose report is returned and written and never reaches `initializeDadsProject`; proven by `src/create-dads.test.ts` "diagnoses an existing project before it writes, and creates the same files either way", which compares the created path lists of a diagnosed and a `--skip-doctor` run.
- INV-CREATE-DADS-16: `--skip-doctor` runs no diagnosis and writes no line, and both `--skip-doctor` and `--today` are refused when repeated or malformed before any project file is written. — enforced by `src/create-dads.ts#readDiagnosisArguments`, `#refuseRepeat`, and `#readDate`, which run before `parseDadsInitializationArguments`; proven by `src/create-dads.test.ts` "skips the doctor entirely for --skip-doctor and refuses a repeated one".
- INV-CREATE-DADS-17: A `--json` run writes nothing before its single output line and carries the report inside it under `doctor`. — enforced by `src/create-dads.ts#announce`, which returns without writing for a `--json` request, and by the `doctor` field of `DadsProjectCreation` that `src/cli.ts` spreads into the envelope; proven by `src/create-dads.test.ts` "carries the report in the --json result and writes nothing before it" and `src/cli.test.ts` "carries the doctor's report inside the --json envelope".
- INV-CREATE-DADS-18: A fresh default creation starts development after installation. A startup failure keeps the installed project and can be retried independently of installation. — enforced by `src/create-dads.ts#prepareDevelopment` and `src/cli.ts#reportCreation`; proven by `src/create-dads.test.ts` "retries the development stack without reinstalling a successful install" and `src/cli.test.ts` "reports a failed Docker startup as incomplete and keeps the installed project".
