# Toolbox invariants

## Project declaration and orientation

- INV-TOOLBOX-1: A project declaration is refused unless every package name and every package root is unique. — enforced by `src/project-orientation.ts#parseDadsProject` through `#assertUniquePackageValues`; proven by `src/project-orientation.test.ts` "rejects an ambiguous package root".
- INV-TOOLBOX-2: Controlled execution semantics require project `schemaVersion` 3; a version 2 task that declares `execution` is refused. — enforced by `src/project-orientation.ts#parseVerificationTask`; proven by `src/verification/boundary-verification.test.ts` "requires schema version 3 for controlled execution semantics".
- INV-TOOLBOX-3: A controlled task must name one of the two mechanically validated adapters, `artifact-provider-v1` or `artifact-consumer-v1`; a self-declared runner kind is refused when the project is parsed. — enforced by `src/verification-policy-parsing.ts#parseControlledExecution`; proven by `src/verification/boundary-verification.test.ts` "rejects self-declared controlled runners outside the mechanical adapter contract".
- INV-TOOLBOX-4: Orientation answers for a path inside a declared root with that package's responsibility, allowed dependencies, verification, and skills, so ownership is resolved from the declaration rather than from source. — enforced by `src/project-orientation.ts#orientProjectPath`; proven by `src/project-orientation.test.ts` "identifies the package and workflow that own a path".
- INV-TOOLBOX-5: An installed capability retains its recipe version, profile, client, and owned files, so a later recipe can tell what it is looking at. — enforced by `src/project-orientation.ts#parseCapabilities`; proven by `src/project-orientation.test.ts` "retains versioned capability recipes for safe future changes".
- INV-TOOLBOX-67: When more than one declared root contains a path, the longest matching root owns it, so a nested package is never shadowed by the package it sits inside. — enforced by `src/project-orientation.ts#orientProjectPath`; proven by `src/project-orientation.test.ts` "gives a nested path to the package with the longest matching root".

## Changed verification planning

- INV-TOOLBOX-6: A default clean scope has no trusted baseline and selects the configured conservative full fallback instead of reporting that nothing needs verification. — enforced by `src/recommend-changed-verification.ts#recommendChangedVerification` and `src/verification/logic/collect-candidate-tasks.ts#selectFullFallbackTasks`; proven by `src/verification/verification-scope.test.ts` "selects the configured full fallback when a default clean scope has no trusted baseline".
- INV-TOOLBOX-7: A changed path that no task declares as an input makes the scope unknown and selects the full fallback; with no fallback configured the plan is incomplete and selects nothing. — enforced by `src/verification/logic/collect-candidate-tasks.ts#selectTasksForChangedPaths` and `#describePlanIssues`; proven by `src/verification/verification-scope.test.ts` "reports unknown scope incomplete when no safe fallback is configured" and `src/agent-workflows.test.ts` "uses conservative verification for an unowned executable change".
- INV-TOOLBOX-8: Selecting a task selects its dependents and its own dependencies, ordered so a provider precedes its consumer; a dependent whose own inputs did not change is `pending-provider` when it is a reuse candidate and `run` otherwise. — enforced by `src/verification/logic/collect-candidate-tasks.ts#includeDependentTasks`, `#includeTaskDependencies`, and `#orderSelectedTasks`; proven by `src/verification/verification-scope.test.ts` "traverses dependent tasks and leaves reuse pending on provider proof" and "includes execution prerequisites before a directly changed task", and `src/agent-workflows.test.ts` "includes consumers when a provider changes".
- INV-TOOLBOX-9: A dependency cycle makes the plan incomplete and is reported, never pruned away. — enforced by `src/verification/logic/collect-candidate-tasks.ts#sortTasksByDependencies` and `#describePlanIssues`; proven by `src/verification/verification-scope.test.ts` "detects dependency cycles instead of pruning them".
- INV-TOOLBOX-10: A task may claim non-source inputs, so a change no package owns still selects the check that covers it rather than falling into unknown scope. — enforced by `src/verification/logic/collect-candidate-tasks.ts#taskMatchesPath`; proven by `src/verification/verification-scope.test.ts` "uses a declared non-source check for documentation history".
- INV-TOOLBOX-66: A task selected twice keeps the more conservative of the two states and both reasons, so a directly changed task that is also a full-fallback task stays `unknown-scope`. — enforced by `src/verification/logic/collect-candidate-tasks.ts#selectTask` through `#chooseMoreConservativeState`; proven by `src/verification/verification-scope.test.ts` "keeps the more conservative state when one task is selected twice".

## Changed scope

- INV-TOOLBOX-11: Changed scope from an explicit base includes committed, staged, unstaged, untracked, and deleted paths and both names of a rename; an invalid explicit base is an error. — enforced by `src/verification/read-changed-scope.ts#readChangedScope`, `#readChangeRecord`, and `#resolveCommit`; proven by `src/verification/verification-scope.test.ts` "finds committed changes on a clean branch from an explicit base", "preserves staged, unstaged, untracked, deleted and both renamed paths", and "rejects an invalid explicit base".
- INV-TOOLBOX-12: Every `git` this package spawns runs against the root it was handed with every `GIT_*` variable removed from its environment, so an inherited hook environment cannot redirect it onto another repository; only `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM`, and `GIT_CONFIG_NOSYSTEM` are carried through, and only for source reads. — enforced by `src/verification/git-environment.ts#environmentWithoutGitVariables`, `src/verification/read-changed-scope.ts#spawnGit`, `src/verification/workspace-git-context.ts#runGitCommand` through `#sourceGitEnvironment`, and `src/doctor/signals/scanners/git-history.ts#runGit`; proven by `src/verification/verification-scope.test.ts` "reads the requested root when the environment names another repository" and `src/verification/workspace-snapshot-git.test.ts` "preserves global source ignores without linking the snapshot to global configuration".

## Workspace snapshots

- INV-TOOLBOX-13: Workspace identity covers the source inventory, the real `HEAD`, and the bytes or link target of every inventoried path, so a commit that changes no file and a deleted tracked file both change it. — enforced by `src/verification/workspace-snapshot.ts#readWorkspaceIdentity`; proven by `src/verification/workspace-snapshot-git.test.ts` "binds workspace identity to HEAD-only changes" and `src/verification/boundary-verification.test.ts` "captures a stable workspace identity while a tracked file is deleted".
- INV-TOOLBOX-14: A workspace symlink whose target resolves outside the project root is refused; a symlink inside the workspace is captured as a symlink rather than followed. — enforced by `src/verification/workspace-snapshot.ts#assertWorkspaceSymlinksStayInsideRoot` and `src/verification/workspace-git-context.ts#copyWorkspaceFiles`; proven by `src/verification/boundary-verification.test.ts` "preserves internal symlinks and rejects graph inputs outside the workspace".
- INV-TOOLBOX-15: A Git workspace snapshot is an independent repository at the captured `HEAD` whose index holds the captured working-source inventory — tracked, staged, untracked-but-not-ignored, and force-added paths — so a root Git check runs against the copied files; a plain directory is captured as a directory with no `.git`. — enforced by `src/verification/workspace-git-context.ts#captureWorkspaceGitSnapshot`, `#synchronizeSnapshotInventory`, and `#copyWorkspaceFiles`; proven by `src/verification/workspace-snapshot-git.test.ts` "gives root Git verification a clean independent repository and captured HEAD", "copies %s source content into the Git inventory so planted references fail", "includes a force-added ignored path with a literal tricky name", and "captures plain directories and lets path based verification scan them".
- INV-TOOLBOX-16: Ignored files are copied but never entered into the snapshot inventory, and a `HEAD` entry that has left the source index is removed from it. — enforced by `src/verification/workspace-git-context.ts#readWorkspaceGitContext` and `#synchronizeSnapshotInventory`; proven by `src/verification/workspace-snapshot-git.test.ts` "does not copy ignored notes or node_modules into the snapshot inventory", "preserves global source ignores without linking the snapshot to global configuration", and "prunes HEAD entries removed from the source index while retaining their ignored bytes".
- INV-TOOLBOX-17: The copied repository keeps no link back to the live one: its remotes and object alternates are gone and its `.git` is a real directory. — enforced by `src/verification/workspace-git-context.ts#captureWorkspaceGitSnapshot`, which clones with `--no-local` and removes the origin section; proven by `src/verification/workspace-snapshot-git.test.ts` "removes live Git remotes and alternates from copied metadata".
- INV-TOOLBOX-18: An unreadable Git inventory or a corrupt `HEAD` is an error, not a fall back to filesystem scanning or a claim of an unborn repository; a genuinely unborn repository is captured without inventing a `HEAD`. — enforced by `src/verification/workspace-git-context.ts#readWorkspaceGitContext` and `#assertUnbornHead`; proven by `src/verification/workspace-snapshot-git.test.ts` "rejects an unreadable Git inventory instead of treating the repository as a directory", "rejects a corrupt existing HEAD instead of classifying it as unborn", and "supports an unborn Git repository without inventing a HEAD".
- INV-TOOLBOX-19: A workspace snapshot is captured only while the checkout identity equals the identity planning saw; its contents stay fixed while the live checkout moves on, and a checkout that changes during verification fails the graph and publishes nothing. — enforced by `src/verification/workspace-snapshot.ts#captureWorkspaceSnapshot` and `src/verification/verify-task-graph.ts#verifyTaskGraph`; proven by `src/verification/workspace-snapshot-git.test.ts` "stays fixed when the live source and index change after capture" and `src/verification/boundary-verification.test.ts` "fails the graph when the live checkout changes during isolated execution".

## Controlled task capture and snapshot identity

- INV-TOOLBOX-20: A controlled request is copied before it is validated and captured, so a caller that mutates it afterwards cannot change what was verified. — enforced by `src/verification/verification-inputs.ts#copyControlledRequest`; proven by `src/verification/verification-receipt.test.ts` "copies environment values, fingerprints them, and never serializes them".
- INV-TOOLBOX-21: A capture is refused before a byte is read when the task is live, declares a secret environment entry, declares an unsupported input role, passes runner arguments, or names an input that escapes the project root or traverses a symlink. — enforced by `src/verification/verification-inputs.ts#validateControlledRequest` and `src/verification/filesystem-guards.ts#resolveInside`, `#assertNoSymlinkComponents`, and `#normalizeRelativePath`; proven by `src/verification/verification-receipt.test.ts` "rejects live tasks, path escapes and symlink inputs", "rejects secret-dependent tasks and unsupported input roles", and "rejects runner arguments that could address the live checkout".
- INV-TOOLBOX-22: Each declared input is captured as a distinct read-only copy, so the snapshot does not observe a later change to the live file. — enforced by `src/verification/snapshot-capture.ts#copyVerificationInputs`; proven by `src/verification/verification-receipt.test.ts` "does not observe a live A to B change after capture".
- INV-TOOLBOX-23: A snapshot identity is independent of declaration order and changes when any execution input changes: input bytes, the input set, the runner version, the required outputs, environment values, prerequisite identities, the timeout, or the bytes of the toolbox performing the verification. — enforced by `src/verification/verification-inputs.ts#createVerificationInputIdentity` and `src/verification/verifier-identity.ts#deriveVerifierIdentity`; proven by `src/verification/verification-receipt.test.ts` "uses a deterministic identity and invalidates every execution input class" and "derives verifier identity from toolbox bytes rather than manifest input", and `src/verification/boundary-verification.test.ts` "invalidates controlled evidence when %s changes" and "invalidates controlled evidence when its environment or runner changes".
- INV-TOOLBOX-24: Environment values are fingerprinted into the identity but never serialized into it or into a receipt; only names are recorded. — enforced by `src/verification/verification-inputs.ts#createVerificationInputIdentity`; proven by `src/verification/verification-receipt.test.ts` "copies environment values, fingerprints them, and never serializes them" and "binds an ABA execution and reused lookup to the captured snapshot".
- INV-TOOLBOX-25: A captured tree that has gained, lost, or altered a byte fails the run instead of being executed or credited. — enforced by `src/verification/snapshot-capture.ts#assertCapturedFilesUnchanged` and `#assertCapturedTreeUnchanged`, reached through `src/verification/verification-inputs.ts#assertSnapshotMatchesIdentity`; proven by `src/verification/verification-receipt.test.ts` "rejects expected-file changes and undeclared files added to a snapshot".
- INV-TOOLBOX-59: A controlled task's own references are mechanically validated before the project is accepted: it runs from the snapshot root with no runner arguments under a command that exactly names its entrypoint; every output prerequisite is a known task, an execution dependency, a controlled task, and a publisher whose artifact this task consumes as an `artifact` input; every published output is one of the task's required outputs; and provider and consumer each match their adapter's reuse, publication, and prerequisite contract. — enforced by `src/verification-policy-parsing.ts#assertExecutionReferences` through `#assertControlledRunner`, `#assertOutputPrerequisites`, `#assertPublishedOutputsAreRequired`, and `#assertAdapterContract`; proven by `src/controlled-execution-references.test.ts` "refuses a controlled runner that does not run from the snapshot root", "refuses a controlled runner that takes arguments", "refuses a command that does not exactly name its runner entrypoint", "refuses an output prerequisite no task in the graph declares", "refuses an output prerequisite that is not an execution dependency", "refuses an output prerequisite that is not a controlled task", "refuses a consumer that does not consume a published output as an artifact", "refuses an output prerequisite that publishes no generated artifact", "refuses a published output the task does not require back", "refuses an artifact provider that is reusable, publishes nothing, or consumes a prerequisite", and "refuses an artifact consumer that is not reusable, publishes output, or consumes nothing".
- INV-TOOLBOX-60: A controlled request is refused when it names a working directory other than the snapshot root, an entrypoint that is not one of its declared inputs, no required outputs, an environment name that is reserved or outside `[A-Z_][A-Z0-9_]*`, or a repeated environment name, prerequisite identity, input path, or output path. — enforced by `src/verification/verification-inputs.ts#validateControlledRequest` through `#assertSnapshotWorkingDirectory`, `#assertEntrypointIsDeclaredInput`, `#assertDeclaredOutputs`, `#validateEnvironment`, and `#assertUniqueValues`; proven by `src/verification/controlled-capture-guards.test.ts` "refuses a working directory other than the snapshot root", "refuses an entrypoint that is not a declared input", "refuses a request that declares no required outputs", "refuses the reserved environment name %s", "refuses an environment name outside the upper-case pattern", "refuses a duplicate environment name", "refuses a duplicate prerequisite identity", "refuses two spellings of the same input path", and "refuses two spellings of the same output path".
- INV-TOOLBOX-61: Dads local state is never a verification input, and a captured file that shares storage with another file is unsafe rather than trusted. — enforced by `src/verification/snapshot-capture.ts#resolveProjectFile` and `#resolveSnapshotFile`; proven by `src/verification/controlled-capture-guards.test.ts` "refuses an input that reaches into Dads local state" and "refuses a captured input that shares storage with another file".

## Controlled execution

- INV-TOOLBOX-26: A controlled runner executes under the Node permission model with read access only to its captured inputs and write access only to its output directory, and with ambient nondeterminism denied: network, wall-clock time, randomness, timers, filesystem metadata, and process timing or identity. — enforced by `src/verification/run-verification-task.ts#runCapturedVerification`, `#permissionModelOption`, and `#controlledBootstrap`; proven by `src/verification/verification-receipt.test.ts` "denies ambient filesystem reads and nondeterministic globals" and "denies $name as an undeclared execution input".
- INV-TOOLBOX-27: An execution that exits nonzero, is signalled, exceeds its timeout, or produces an output set other than the declared one is a failure and leaves no receipt behind. — enforced by `src/verification/run-verification-task.ts#runCapturedVerification` and `#fingerprintVerificationOutputs`; proven by `src/verification/verification-receipt.test.ts` "treats corrupt evidence and timed out executions as non-success", "does not publish a receipt when the reusable task fails", and "does not publish a receipt when a required output is missing".
- INV-TOOLBOX-62: A controlled runner may import only `node:assert`, `node:assert/strict`, `node:fs`, `node:path`, and literal local specifiers; any other builtin, any package, and any dynamic import whose specifier is not a literal fails the run before the runner starts. — enforced by `src/verification/run-verification-task.ts#assertAllowedControlledImports`, `#assertAllowedModuleSource`, and `#assertAllowedImportSpecifier`; proven by `src/verification/controlled-import-allowlist.test.ts` "allows the allowlisted builtins and a literal relative import", "refuses a builtin the allowlist does not name", "refuses a package import the allowlist does not name", "refuses a dynamic import whose specifier is not a literal", and "refuses a literal dynamic import of a builtin outside the allowlist".
- INV-TOOLBOX-28: Shell and live tasks execute every time, and a command that cannot be launched is a failure rather than a pass. — enforced by `src/verification/run-verification-task.ts#runVerificationTask` and `src/verification/logic/decide-task-reuse.ts#decideTaskReuse`; proven by `src/verification/verification-scope.test.ts` "reports command launch failures as non-success" and `src/verification/boundary-verification.test.ts` "blocks dependents after provider failure and never reuses live or full tasks".

## Receipts

- INV-TOOLBOX-29: A receipt exists only for a successful execution whose snapshot identity matches its own and whose outputs are exactly the required ones; a claimed success carrying a nonzero exit code is refused. — enforced by `src/verification/verification-receipt.ts#createSuccessfulVerificationReceipt` and `#assertSuccessfulExecution`; proven by `src/verification/verification-receipt.test.ts` "rejects a dishonest success state and changed outputs for one snapshot" and "treats corrupt evidence and timed out executions as non-success".

- INV-TOOLBOX-32: Republishing the same snapshot with different inputs or outputs is refused rather than overwriting the receipt that already exists. — enforced by `src/verification/receipt-store.ts#readExistingReceipt`; proven by `src/verification/verification-receipt.test.ts` "rejects a dishonest success state and changed outputs for one snapshot".
- INV-TOOLBOX-63: Publishing a receipt takes an exclusive per-task lock and writes through a private temporary file that is fsynced and renamed, so a task another run already owns is refused and no partial receipt is ever left behind. — enforced by `src/verification/receipt-store.ts#publishSuccessfulVerificationReceipt`, `#acquireTaskLock`, and `#writeAtomicFile`; proven by `src/verification/receipt-store-writes.test.ts` "refuses to publish while another run owns the task lock", "releases the task lock and leaves only the finished receipt behind", and "leaves no partial receipt behind when a republish is refused".
- INV-TOOLBOX-64: Evidence that failed to parse is removed rather than left in place to be read again. — enforced by `src/verification/execute-graph-task.ts#discardInvalidReceipt`; proven by `src/verification/boundary-verification.test.ts` "removes invalid evidence instead of leaving it to be read again".
