# Audit invariants

Rules about the universal row-level audit log and the mandatory actor context every pooled connection carries, enforced by the `audit_record` trigger, the attributed pool, and the coverage detector.

- INV-AUDIT-1: Each configured public table carries exactly one `audit_record` trigger, and application exclusions carry none — enforced by `src/lib/database/configure-audit-triggers.ts`, `src/lib/database/configure-audit-triggers.integration.test.ts`
- INV-AUDIT-2: `audit_log` rows are never updated or deleted; the only removal path is TRUNCATE by test infrastructure — enforced by `src/lib/database/migrations/20260910233455_audit.migration.ts`, `src/lib/database/audit-log.integration.test.ts`
- INV-AUDIT-3: An audited write requires a stamped actor and request identity. An unstamped write fails without leaving a row — enforced by `src/lib/database/migrations/20260910233455_audit.migration.ts`, `src/lib/database/audit-log.integration.test.ts`.
- INV-AUDIT-4: Every connection checkout from an attributed pool re-stamps `dads.audit_actor` from the current context (or empty when there is none) before the first statement, so an actor never leaks from one context to the next on a reused connection — enforced by `packages/server/postgres/src/lib/attributed-pool.ts`, `packages/server/postgres/src/lib/attributed-pool.integration.test.ts`
- INV-AUDIT-5: `row_key` contains the identity columns explicitly configured for that table — enforced by `src/lib/database/migrations/20260910233455_audit.migration.ts`, `src/lib/database/audit-log.integration.test.ts`
- INV-AUDIT-6: `request_log` rows are written off the request path in bounded batches: past the buffer ceiling the OLDEST row is dropped with one warning per episode, a failed batch is logged and never raised, a request id already stored is left alone, and `close()` drains what is buffered — enforced by `src/lib/request-log/postgres-request-log-sink.ts#PostgresRequestLogSink`, `src/lib/request-log/postgres-request-log-sink.integration.test.ts`
- INV-AUDIT-7: Every job run is attributed `system` / `job:<name>` with a fresh request id, stamped by the driver before `run` is called — enforced by `packages/server/job-queue/src/lib/job-actor.ts#jobRunActor`, `packages/server/job-queue/src/lib/in-process-job-queue.test.ts`, `packages/server/job-queue/src/lib/bullmq-job-queue.integration.test.ts`
- INV-AUDIT-8: `request_log` work columns are null when nothing measured the request and never zero, so a row written by a build without the counters reads as "not measured" rather than as "did no work" — enforced by `packages/server/http/src/lib/request-log/request-record.ts#whatItCost`, `packages/server/http/src/lib/request-log/request-record.test.ts`, `src/lib/request-log/postgres-request-log-sink.integration.test.ts`
- INV-AUDIT-9: A fault fingerprint is alerted at most once per origin — `known_fault_fingerprints` is written only after the mail is enqueued, is never pruned, and is what the sweep filters on, so neither a longer window nor the fault tables aging their rows out can produce a second alert — enforced by `src/lib/database/readers/drizzle-fault-alert-reader.ts#DrizzleFaultAlertReader`, `src/lib/database/readers/drizzle-fault-alert-reader.integration.test.ts`, `src/lib/fault-alerts/alert-new-faults.job.test.ts`
- INV-AUDIT-10: An allowed request is attributed to an audit actor — a subject kind no composed handler names, or two subjects that disagree, is attributed to the identity the credential proved, and to `anonymous` only when none did, because returning nothing would make the trigger refuse a properly authenticated write — enforced by `src/lib/actor/compose-subject-to-audit-actor.ts#composeSubjectToAuditActor`, `src/lib/actor/compose-subject-to-audit-actor.test.ts`
- INV-AUDIT-11: An application scope sees only rows whose captured dimensions match every requested dimension. An empty scope or a change to a requested dimension is excluded — enforced by `src/lib/database/configure-audit-triggers.integration.test.ts`.
