# HTTP edge invariants

- INV-HTTP-1: A route declared with an authorization context resolves current domain-owned authority before its single-resource check or collection lookup; missing, malformed, duplicate or refused context never falls back to the global user, and an absent resolver is a wiring failure — enforced by `src/lib/request-pipeline/enforce-access.ts#enforceAccess`, `src/lib/request-pipeline/acting-company-access.test.ts`, `src/lib/request-pipeline/header-context.test.ts`
- INV-HTTP-2: Context-bound handlers receive business authority and authenticated identity separately; audit identity and per-user rate budgets never change when the same user changes context — enforced by `src/lib/route/route-execution.ts#resolveAuthenticatedSubject`, `src/lib/request-pipeline/register-routes.ts`, `src/lib/request-pipeline/acting-company-routes.test.ts`
- INV-HTTP-3: A subject resolver that reports its auth method owns the answer outright — its "nobody" is a 401, never a second opinion from the narrow `resolve`; the reported permission, resource, access kind and auth method are recorded, never consulted, so allow and deny outcomes are identical with or without them — enforced by `src/lib/request-pipeline/enforce-access.ts#resolveAuthenticatedCaller`, `src/lib/request-pipeline/enforce-access.test.ts`
- INV-HTTP-4: A captured request row reads only the `user-agent`, `sec-ch-ua*`, `accept-language`, `x-forwarded-for` and `x-client-context` headers, and stores the matched route pattern rather than the raw url — no cookie, authorization header, query string, or body ever reaches `request_log` — enforced by `src/lib/request-log/request-record.ts#buildRequestRecord`, `src/lib/request-log/request-record.test.ts`
- INV-HTTP-5: Request capture runs after the response and can never change it: a missing sink, a throwing sink, or an unreadable client-context header drops the row and logs, and the client sees the answer it would have seen with no capture at all — enforced by `src/lib/request-log/capture-request-record.ts#captureRequestRecord`, `src/lib/request-log/capture-request-record.test.ts`
- INV-HTTP-6: Every request enters the audit context as `anonymous` at ingress, the handler runs as the resolved subject once a mapper is wired, and no request inherits the previous request's actor — enforced by `src/lib/create-http-app.ts`, `src/lib/request-pipeline/carry-audit-actor.ts`, `src/lib/request-pipeline/carry-audit-actor.test.ts`
- INV-HTTP-7: A verb route may declare a bounded request body allowance without changing the application default for other routes; both configured limits remain enforced — enforced by `src/lib/request-pipeline/register-routes.ts#toFastifyRoute`, `src/lib/request-pipeline/route-body-limit.test.ts`
- INV-HTTP-8: A feature preview id is resolved once per request through the application's resolver and lives only in that request's context; an id that resolves to nothing is answered as no preview with the dropped header; while a view-only preview applies, every write route not marked `writesDuringFeaturePreview: "allowed"` is refused with `FEATURE_PREVIEW_READ_ONLY` before its handler runs — enforced by `src/lib/request-pipeline/feature-state-preview.ts#carryFeatureStatePreview`, `src/lib/request-pipeline/feature-state-preview.test.ts`
