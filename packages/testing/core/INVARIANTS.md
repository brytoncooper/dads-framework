# Dads Testing invariants

This package is a facade over a native engine. Selection and execution semantics
are enforced in the Rust crates under `crates/` and reached through the versioned
JSON protocol; the entries below name the enforcing file wherever it lives. A
`fixtures/testing-soundness/cases.json` case id names a case in the sealed
soundness corpus, executed by `scripts/testing/testing-soundness.mjs` and gated by
`scripts/testing/verify-testing-release.mjs`.

## Selection

- INV-TESTING-1: A changed path selects the tasks of the project whose declared root owns it, and a changed path no declared project owns selects the manifest's complete fallback — enforced by `crates/dads-testing-core/src/plan/widening.rs#own_changed_paths`, proven by `crates/dads-testing-core/src/tests/planning.rs#changed_owned_files_widen_reachability_and_unknown_files_fallback` and corpus case `unowned-path`.
- INV-TESTING-2: A module the dependency graph proves reachable from a changed path selects its owning project, and a reachable module no project owns selects the complete fallback — enforced by `crates/dads-testing-core/src/plan/widening.rs#record_reachable_paths`, proven by `crates/dads-testing-core/src/tests/graph_widening.rs#static_importers_select_their_reachability_tasks_across_projects` and corpus cases `direct-ts-import`, `transitive-ts-import`, and `type-only-dependency`.
- INV-TESTING-3: When no language frontend answers, or the frontend does not cover a changed path, every changed project widens through its declared `fallbackDependencies` and the plan carries an issue naming the path that could not be proven — enforced by `crates/dads-testing-core/src/plan/widening.rs#record_missing_frontend` and `#record_uncovered_paths`, with the transitive widening in `crates/dads-testing-core/src/plan.rs#propagate_fallback_dependents`, proven by `crates/dads-testing-core/src/tests/graph_widening.rs#graph_uncertainty_widens_only_through_declared_project_dependencies` and corpus cases `unsupported-language`, `delete-file`, and `rename-file`.
- INV-TESTING-4: A graph uncertainty on a path a project owns widens only that project's declared dependency closure; an uncertainty on a path no project owns selects the complete fallback — enforced by `crates/dads-testing-core/src/plan/widening.rs#record_reachable_uncertainties`, proven by `crates/dads-testing-core/src/tests/graph_widening.rs#unreached_unbounded_import_uncertainty_widens_its_owner_project` and corpus cases `nonliteral-dynamic-import`, `alias-import`, and `unresolved-local-import`.
- INV-TESTING-5: The only skip a plan emits is `skip-proven-unaffected`; a task named by `--task` and a task whose `impact.mode` is `always` are selected in every plan, and every selected task also selects its declared prerequisite closure — enforced by `crates/dads-testing-core/src/plan/decisions.rs#explain_decisions`, `crates/dads-testing-core/src/plan.rs#add_prerequisites`, and `crates/dads-testing-core/src/plan.rs#select_tasks`, proven by `crates/dads-testing-core/src/tests/planning.rs#direct_input_includes_prerequisites_and_always_tasks`, `crates/dads-testing-core/tests/changed_file_explanation.rs#retains_proven_unaffected_explanations_without_changes`, and corpus case `unrelated-sibling-export`.
- INV-TESTING-6: A path is owned by the deepest declared project root, a root of `.` owns the whole workspace, and two equally deep roots claiming one path own nothing so the caller must widen instead of guessing — enforced by `src/path-ownership.ts#owningProjectForPath` and `crates/dads-testing-core/src/scope.rs#deepest_project_for_path`, proven by `src/path-ownership.test.ts` "gives a path to the deepest matching project" and "answers nothing when two equally deep roots both match", and `crates/dads-testing-core/src/tests/planning.rs#changed_nested_project_uses_deepest_owner_when_parent_is_listed_first`.

## Execution

- INV-TESTING-7: `run` executes every selected task again — no result is cached or reused — and a failed or blocked prerequisite blocks its dependents while independent tasks keep running — enforced by `crates/dads-testing-core/src/scheduler.rs#run_plan`, proven by `crates/dads-testing-core/src/tests/running.rs#run_does_not_reuse_a_previous_task_result` and `#run_continues_independent_work_and_blocks_failed_dependents`.
- INV-TESTING-30: A `jobs` of zero is refused by the planner and, independently, by the scheduler, and a request that names no limit runs at the protocol's fixed default of four workers, so the same manifest behaves the same way on every machine — enforced by `crates/dads-testing-core/src/plan.rs#build_plan` and `crates/dads-testing-core/src/scheduler.rs#job_limit` (`DEFAULT_JOBS`), proven by `crates/dads-testing-core/tests/request_refusals.rs#a_zero_job_limit_is_refused_while_the_plan_is_built`, and `crates/dads-testing-core/src/tests/running.rs#the_scheduler_refuses_a_zero_job_limit` and `#run_uses_four_workers_when_no_limit_is_requested`.

## The native boundary

- INV-TESTING-8: The plan and run wire contract is protocol schemaVersion 1, and a published key is never renamed, dropped, or re-valued while that version holds — enforced by `crates/dads-testing-core/src/protocol.rs` (`PROTOCOL_SCHEMA_VERSION` and its serde attributes), proven by `crates/dads-testing-core/tests/wire_golden.rs#the_live_plan_response_still_carries_every_key_the_golden_records` and `#the_protocol_schema_version_never_falls_below_the_recorded_floor`.
- INV-TESTING-9: Each `plan` or `run` operation makes exactly one request to the native process, and an option the caller did not set is omitted from that request rather than sent as null — enforced by `src/testing-api.ts#invokeNativeTestingEngine` and `#toNativeRequest`, proven by `src/cli.test.ts` "writes the versioned envelope and sends one plan request".
- INV-TESTING-10: A field the engine did not report means the engine is older than this facade, not that the fact does not hold: task ownership and causes stay optional, and an issue without a declared `severity` or `scope` is classified from its code — enforced by `src/plan-issues.ts#issueSeverity` and `#issueScope`, proven by `src/plan-issues.test.ts` "derives severity from the issue code for an older engine" and "derives scope from the issue code for an older engine", and `src/testing-api.test.ts` "reads task ownership, causes, and located issues from a newer engine".
- INV-TESTING-11: The native engine is the optional package matching the host platform and architecture; an unsupported target or a missing package is an error naming that package, and an explicit `nativeBinary` or `DADS_TEST_NATIVE_BINARY` must point at an existing file — enforced by `src/native-platform.ts#resolveNativeTestingBinary`, `#nativePackageDefinitionForPlatform`, and `#requireExistingDevelopmentBinary`, proven by `src/native-platform.test.ts` "maps every supported platform tuple to one optional package", "reports a missing optional package precisely", and "accepts an existing development binary without spawning it".
- INV-TESTING-33: A development binary replaces the platform package rather than backing it up — an explicit `nativeBinary`, then `DADS_TEST_NATIVE_BINARY`, are each read before any package lookup runs — and every resolution names the source that supplied the path, so a failure says which input was wrong — enforced by `src/native-platform.ts#resolveNativeTestingBinary`, `#developmentBinaryFor`, and `#requireExistingDevelopmentBinary`, proven by `src/native-platform.test.ts` "uses DADS_TEST_NATIVE_BINARY in place of a missing platform package", "reads an explicit nativeBinary before the variable", and "names the source that supplied a path with no file behind it".
- INV-TESTING-28: A caller only ever receives a result the engine produced for the operation it asked about: a response whose `schemaVersion` is not the protocol version, a non-ok envelope, an envelope with no result, a result for a different operation, a `run` result without run details, output that is not JSON, and JSON that is not the envelope are each an error naming what was wrong — enforced by `src/testing-api.ts#requireResultFor`, `#isNativeResponse`, `#runNativeProcess`, and `#runTesting`, proven by `src/testing-api-refusals.test.ts` "refuses a native response whose schemaVersion is not the protocol version", "refuses a non-ok envelope, reporting the engine's own error message", "refuses an ok envelope that carries no result at all", "refuses a result for an operation the caller did not request", "refuses a run result that carries a plan but no run details", "refuses a response that is not JSON, quoting what the engine wrote to stderr", and "refuses JSON that is not the native envelope".
- INV-TESTING-31: The engine refuses a request it cannot honor before it reads a manifest or resolves a scope — a `schemaVersion` other than 1, a `--head` with no `--base`, and `--all` combined with `--base` or `--head` — and every refusal leaves through the protocol as an `ok: false` response rather than a panic — enforced by `crates/dads-testing-core/src/execute.rs#execute`, proven by `crates/dads-testing-core/tests/request_refusals.rs#an_unsupported_request_schema_version_is_refused`, `#a_head_without_a_base_is_refused`, and `#all_combined_with_a_base_or_a_head_is_refused`.
- INV-TESTING-32: The `dad-test` binary appends the snapshot store's issues after the core's own, so an issue index a decision cites still names the issue the planner meant — enforced by `crates/dads-testing-cli/src/main.rs`, proven by `crates/dads-testing-cli/tests/plan_issue_order.rs#store_issues_are_appended_after_the_core_issues_a_decision_cites`.
- INV-TESTING-34: The `dad-test` binary analyzes a dependency graph only when the manifest declares a `reachability` task; a manifest whose tasks are all `always`, `changed-files`, or `project` never reads one, so no workspace is parsed and no snapshot is read or written, and the plan carries a `graph-analysis-unneeded` issue instead — enforced by `crates/dads-testing-cli/src/main.rs#analyze_workspace`, `crates/dads-testing-core/src/execute.rs#graph_analysis_can_change_the_plan`, and `crates/dads-testing-core/src/manifest.rs#declares_graph_reader`, proven by `crates/dads-testing-core/src/tests/graph_analysis_need.rs#an_owned_change_plans_identically_with_and_without_a_graph`, `#an_unowned_change_still_selects_the_complete_fallback_without_a_graph`, `#a_direct_task_input_still_selects_its_closure_without_a_graph`, and `crates/dads-testing-cli/tests/graph_analysis_skip.rs#a_manifest_without_a_graph_reader_skips_the_analysis_and_says_so` and `#one_reachability_task_still_gets_its_graph_analyzed`.
- INV-TESTING-35: A persisted graph snapshot is trusted only when the workspace it was written for, the testing manifest's contents — its bytes, never the path it was read from — and the frontend version all still match; a trusted snapshot is reused as it stands only when the head sha, the scope signature, and every changed-path fingerprint match as well, a difference in the fingerprints alone is patched over exactly the paths that differ, and any other difference is rebuilt. The resolved comparison base is part of that scope signature because the snapshot carries the base-relative changed-export evidence a plan is seeded from, so two bases at one head are two analyses rather than one asked about twice — enforced by `crates/dads-testing-store/src/lib.rs#establish_identity`, `#choose_snapshot_plan`, and `#plan_for_trusted_snapshot`, with `crates/dads-testing-store/src/snapshot.rs#manifest_digest`, `#snapshot_matches`, and `#patchable_paths`, over the state `crates/dads-testing-store/src/git_state.rs#indexed_git_state` reads, proven by `crates/dads-testing-store/src/tests.rs#the_manifest_identity_is_its_contents_and_not_its_path`, `#incompatible_schema_is_rejected_before_reuse`, `#stale_frontend_version_snapshot_is_rebuilt`, `#moved_base_ref_rebuilds_instead_of_reusing_persisted_graph`, `#two_comparison_bases_at_one_head_never_share_a_snapshot`, `#changed_head_with_clean_worktree_rebuilds_instead_of_zero_path_patch`, `#unchanged_head_and_scope_incrementally_patch_changed_working_file`, and `crates/dads-testing-store/src/deleted_path_tests.rs#deleted_file_is_reused_until_restored`.
- INV-TESTING-36: A comparison the snapshot key cannot describe is analyzed in full and never persisted: a request naming a `--head`, an `--all` request, and any changed path the store cannot fingerprint with certainty each leave the run with a complete analysis, a fallback action, and a `snapshot-noncurrent-scope-not-persisted` issue, rather than writing a snapshot keyed as though it described the current head — enforced by `crates/dads-testing-store/src/lib.rs#analyze_without_snapshot` over `crates/dads-testing-store/src/git_state.rs#indexed_git_state` and `#fingerprint_changed_path`, proven by `crates/dads-testing-store/src/tests.rs#a_requested_head_is_analyzed_without_writing_a_snapshot` and `crates/dads-testing-store/src/deleted_path_tests.rs#missing_descendant_of_symlink_fails_closed`.

## What the commands refuse

- INV-TESTING-12: Every command answers in one versioned JSON envelope under `--json`, including when argument parsing failed before a command was chosen; the human form is explicitly not the contract — enforced by `src/dad-test-cli.ts#runDadTestCli` and `src/cli-output.ts#writeCommandSuccess`, proven by `src/cli.test.ts` "writes the versioned envelope and sends one plan request", "names every operation when the operation is missing or unknown", and "prints a human first line without --json".
- INV-TESTING-13: An argument no command declares, a repeated single-value option, an option missing its value, and a `--jobs` that is not a positive integer are refused with exit code 1 and nothing on stdout — enforced by `src/cli-arguments.ts#requireDeclaredKind`, `#requireUsableValue`, and `#readPositiveInteger`, proven by `src/cli.test.ts` "rejects plan --what", "rejects plan --base", "rejects plan --base a --base b", "rejects plan --jobs 0", and "rejects plan extra".
- INV-TESTING-14: `explain` fails with the manifest's own error when the manifest cannot be read, rather than printing a thinner explanation — enforced by `src/commands/explain.ts#explainCommand`, proven by `src/commands/explain.test.ts` "fails with the manifest error when the manifest is missing".
- INV-TESTING-15: `explain` never mixes engine-reported and reconstructed causes — one task without `causes` makes the whole explanation `derived` and the explanation says which mode it is in — a cause naming an issue index the plan does not contain is reported as its own uncertainty rather than dropped, and a module-scope uncertainty about another project is never cited as evidence for this one — enforced by `src/explain-plan.ts#explainPlan`, `#explainIssueAt`, and `#moduleUncertaintyIssues`, proven by `src/explain-plan.test.ts` "reports engine detail and maps every cause the engine proved", "counts an empty cause list as reported rather than missing", "reports an issue reference the plan cannot satisfy instead of failing", and "keeps a module uncertainty about another project out of this one".
- INV-TESTING-16: `--report` is the only reason `plan` and `run` read the manifest; without it their output is exactly what it was before the option existed, and `--report` without a path embeds the report without writing a file — enforced by `src/commands/plan-run.ts#buildReportIfRequested`, proven by `src/commands/plan-run.test.ts` "leaves plan --json output unchanged when --report is absent", "writes the report file and embeds it when --report has a value", and "embeds the report without writing a file when --report has no value".
- INV-TESTING-17: The report's project closure widens to every declared project whenever a changed path is unowned or a full-fallback plan has no changed paths to attribute, so its `reductionRatio` is never measured against a closure narrower than the evidence supports — enforced by `src/testing-report.ts#buildProjectClosure`, proven by `src/testing-report.test.ts` "widens the project closure to every project when a changed path is unowned" and "widens the project closure to every project for a full-fallback --all plan with no changed paths".
- INV-TESTING-29: A project closure that declares no tasks reports `reductionRatio: null` rather than a ratio over zero, so a reader is never given a number no evidence supports — enforced by `src/testing-report.ts#buildProjectClosure`, proven by `src/testing-report.test.ts` "reports no reduction ratio when the project closure declares no tasks at all".

## The manifest

- INV-TESTING-18: A manifest is rejected rather than partly read — an unknown key, a `schemaVersion` other than 1, or a wrongly typed field fails the parse with the document named — the manifest path must resolve inside the workspace root, and serializing omits defaulted keys and round-trips — enforced by `src/testing-manifest.ts#parseTestingManifest`, `#rejectUnknownKeys`, `#readTestingManifest`, and `#serializeTestingManifest`, proven by `src/testing-manifest.test.ts` "rejects an unknown key rather than ignoring it", "rejects an unsupported schema version and a wrong type", "refuses a manifest path outside the workspace", "round-trips the testing fixture manifest", and "omits defaulted keys when serializing".
- INV-TESTING-19: A manifest must declare at least one task, unique project and task ids inside the identifier charset, workspace-relative paths without parent traversal, resolvable project and dependency references, no self-dependency, no task cycle, `changed-files` impact with at least one path, and a `workspace.fullFallback.taskIds` naming every declared task exactly once — enforced by `src/init/check-testing-manifest.ts#checkTestingManifest`, mirroring `crates/dads-testing-core/src/manifest.rs`, proven by `src/init/check-testing-manifest.test.ts` "accepts a manifest the native engine accepts" and its per-violation cases, among them "reports a dependency cycle", "reports a full fallback that omits a task", and "reports a manifest without tasks".

## What `init` refuses

- INV-TESTING-20: `init` refuses to overwrite an existing manifest without `--force`, and refuses before generating anything so the refusal leaves no report behind either — enforced by `src/init/init-testing-manifest.ts#initTestingManifest`, proven by `src/init/init-testing-manifest.test.ts` "refuses to replace a manifest without force, and replaces it with force".
- INV-TESTING-21: `init` refuses a workspace containing `nx.json`, writing the report that says why and no manifest, and leaving an existing manifest untouched even with `--force`; a workspace declaring no recognized `test`, `typecheck`, `lint`, or `build` script likewise gets the report and no manifest — enforced by `src/init/init-testing-manifest.ts#requireStandaloneWorkspace` and `#requireInferredManifest`, proven by `src/init/nx-workspace-refusal.test.ts` "does not present root script discovery as coverage of an Nx workspace" and "preserves an existing manifest when Nx discovery is refused with force", and `src/init/init-testing-manifest.test.ts` "writes only the report when nothing declares a recognized script".
- INV-TESTING-22: A generated manifest reaches its final path only after the structural check passes and, where the native engine is installed, only after that engine has planned against a temporary copy; a rejected manifest leaves the report and no manifest — enforced by `src/init/init-testing-manifest.ts#requireStructurallyValid`, `#writeEngineChecked`, and `#validateWithNativeEngine`, proven by `src/init/init-testing-manifest.test.ts` "validates the generated manifest with the native engine", "leaves no manifest behind when the engine rejects it", and "takes the structural path when no native engine is resolved".
- INV-TESTING-23: Generated files are written through unique temporary files and renamed into place, so a reader never observes a half-written file; a failure removes every temporary file the call created and writes none of the outputs — enforced by `src/write-files-atomically.ts#writeFilesAtomically`, proven by `src/write-files-atomically.test.ts` "removes every temporary file and writes nothing when one output fails".
- INV-TESTING-24: A workspace declaration `init` cannot read with certainty refuses at the file and line it appears on, and a pattern it cannot compile is dropped and named in the report, rather than generating a manifest that silently omits projects — enforced by `src/init/pnpm-workspace-yaml.ts#parsePnpmWorkspaceFile`, `src/init/workspace-glob.ts#compileWorkspaceGlob`, and `src/init/detect-workspace.ts#patternIsSupported`, proven by `src/init/pnpm-workspace-yaml.test.ts` "refuses an anchor at the file and line it appears on" and "refuses a file without a packages key", and `src/init/workspace-glob.test.ts` "names the pattern it cannot compile".
- INV-TESTING-25: Two packages that resolve to the same project id are an error rather than a silent rename, because two projects sharing an id would silently share a fallback — enforced by `src/init/project-ids.ts#assignProjectIds`, proven by `src/init/project-ids.test.ts` "refuses two packages that resolve to the same id".
- INV-TESTING-26: A generated project falls back to every project it declares a package dependency on or a TypeScript project reference to, and a package's `test` task depends on that package's own `typecheck` task where one exists — enforced by `src/init/infer-one-package.ts#fallbackDependenciesOf` and `#inferOneTask`, proven by `src/init/infer-testing-manifest.test.ts` "falls back through package dependencies and project references" and "runs a package's test after its own typecheck".
- INV-TESTING-27: Every `dad-test` command and every option it parses, including the `--json` the parser accepts everywhere, is readable from the CLI itself, so a command or option cannot ship undocumented — enforced by `src/dad-test-cli.ts#listDadTestCommands` and `scripts/checks/check-docs.mjs#checkDocs`, proven by `scripts/checks/check-docs.test.mjs` "a README that omits an option fails".
