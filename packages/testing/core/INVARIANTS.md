# Dads Testing invariants

This package is a facade over a native engine. Selection and execution semantics
are enforced in the Rust crates under `crates/` and reached through the versioned
JSON protocol; the entries below name the enforcing file wherever it lives. A
`fixtures/testing-soundness/cases.json` case id names a case in the sealed
soundness corpus, executed by `scripts/testing/testing-soundness.mjs` and gated by
`scripts/testing/verify-testing-release.mjs`.

## Selection

- INV-TESTING-1: A changed path selects the tasks of the project whose declared root owns it, and a changed path no declared project owns selects the manifest's complete fallback — enforced by `crates/dads-testing-core/src/plan/widening.rs#own_changed_paths`, proven by `crates/dads-testing-core/src/tests/planning.rs#changed_owned_files_widen_reachability_and_unknown_files_fallback` and corpus case `unowned-path`.
- INV-TESTING-2: A module the dependency graph proves reachable from a changed path selects its owning project, and a reachable module no project owns selects the complete fallback — enforced by `crates/dads-testing-core/src/plan/widening.rs#record_reachable_paths`, proven by `crates/dads-testing-core/src/tests/graph_widening.rs#static_importers_select_their_reachability_tasks_across_projects` and corpus cases `direct-ts-import`, `transitive-ts-import`, and `type-only-dependency`.
- INV-TESTING-3: When no language frontend answers in a multi-project workspace, non-ignored changed paths fail closed to the manifest's complete fallback so projects without manual `fallbackDependencies` never silently skip affected downstream tasks; when the frontend answers but does not cover a changed path, every changed project widens through its unified dependency closure (`fallbackDependencies` and graph imports) and the plan carries an issue naming the path that could not be proven — enforced by `crates/dads-testing-core/src/plan/widening_fs.rs#record_missing_frontend` and `crates/dads-testing-core/src/plan/widening.rs#record_uncovered_paths`, with the transitive widening in `crates/dads-testing-core/src/plan.rs#propagate_fallback_dependents`, proven by `crates/dads-testing-core/src/tests/graph_widening.rs#static_importers_select_their_reachability_tasks_across_projects`, `crates/dads-testing-core/src/tests/graph_widening.rs#graph_uncertainty_widens_only_through_declared_project_dependencies`, and corpus cases `unsupported-language`, `delete-file`, and `rename-file`.
- INV-TESTING-4: A graph uncertainty on a path a project owns widens only that project's declared dependency closure; an uncertainty on a path no project owns selects the complete fallback — enforced by `crates/dads-testing-core/src/plan/widening.rs#record_reachable_uncertainties`, proven by `crates/dads-testing-core/src/tests/graph_widening.rs#unreached_unbounded_import_uncertainty_widens_its_owner_project` and corpus cases `nonliteral-dynamic-import`, `alias-import`, and `unresolved-local-import`.
- INV-TESTING-5: The only skip a plan emits is `skip-proven-unaffected`; a task named by `--task` and a task whose `impact.mode` is `always` are selected in every plan, and every selected task also selects its declared prerequisite closure — enforced by `crates/dads-testing-core/src/plan/decisions.rs#explain_decisions`, `crates/dads-testing-core/src/plan.rs#add_prerequisites`, and `crates/dads-testing-core/src/plan.rs#select_tasks`, proven by `crates/dads-testing-core/src/tests/planning.rs#direct_input_includes_prerequisites_and_always_tasks`, `crates/dads-testing-core/tests/changed_file_explanation.rs#retains_proven_unaffected_explanations_without_changes`, and corpus case `unrelated-sibling-export`.
- INV-TESTING-6: A path is owned by the deepest declared project root, a root of `.` owns the whole workspace, and two equally deep roots claiming one path own nothing so the caller must widen instead of guessing — enforced by `src/path-ownership.ts#owningProjectForPath` and `crates/dads-testing-core/src/scope.rs#deepest_project_for_path`, proven by `src/path-ownership.test.ts` "gives a path to the deepest matching project" and "answers nothing when two equally deep roots both match", and `crates/dads-testing-core/src/tests/planning.rs#changed_nested_project_uses_deepest_owner_when_parent_is_listed_first`.

## Execution

- INV-TESTING-7: `run` executes every selected task again — no result is cached or reused — and a failed or blocked prerequisite blocks its dependents while independent tasks keep running — enforced by `crates/dads-testing-core/src/scheduler.rs#run_plan`, proven by `crates/dads-testing-core/src/tests/running.rs#run_does_not_reuse_a_previous_task_result` and `#run_continues_independent_work_and_blocks_failed_dependents`.
- INV-TESTING-30: A `jobs` of zero is refused by the planner and, independently, by the scheduler, and a request that names no limit runs at the protocol's fixed default of four workers, so the same manifest behaves the same way on every machine — enforced by `crates/dads-testing-core/src/plan.rs#build_plan` and `crates/dads-testing-core/src/scheduler.rs#job_limit` (`DEFAULT_JOBS`), proven by `crates/dads-testing-core/tests/request_refusals.rs#a_zero_job_limit_is_refused_while_the_plan_is_built`, and `crates/dads-testing-core/src/tests/running.rs#the_scheduler_refuses_a_zero_job_limit` and `#run_uses_four_workers_when_no_limit_is_requested`.
- INV-TESTING-37: Runtime read guarding (`--enforce-declared-reads` or `workspace.enforceDeclaredReads`) injects zero preload hooks on default runs and, when enabled on Node/Vitest test tasks, fails any task with undeclared workspace reads after collecting every violation in one run and never persists a cache receipt for that task — enforced by `crates/dads-testing-core/src/scheduler/read_guard.rs#apply_read_guard_result` and `crates/dads-testing-core/src/scheduler/read_guard_allowlist.rs`, proven by `crates/dads-testing-core/tests/read_guard.rs#enforce_lists_multiple_violations_blocks_cache_and_passes_once_declared` and `#manifest_enforce_default_and_no_enforce_override_and_audit_mode`.
- INV-TESTING-38: Content-hashed task receipts (`dads-testing-receipt-v5`) bind file content SHA-256, Unix executable permission bits, ambient runtime environment variables (`TZ`, `NODE_ENV`, `NODE_OPTIONS`, `LC_ALL`, `LANG`), gitignored `impact.paths` globs, ancestor config/dotenv files, and ambient `.d.ts` declarations for typecheck tasks — enforced by `crates/dads-testing-store/src/receipts.rs#FileReceiptStore`, `crates/dads-testing-store/src/receipt_cache.rs#inspect_and_hash_file`, and `crates/dads-testing-store/src/receipt_policy.rs`, proven by `crates/dads-testing-store/tests/planner_cache_invariant.rs#planner_cache_invariant_holds_for_every_dependency_and_input_channel`.
- INV-TESTING-39: A precomputed `--plan-file` that skips at least one task is verified against the workspace Git `HEAD` and non-ignored working-tree fingerprint (excluding the `--plan-file` artifact itself) and fails closed if the workspace changed after planning — enforced by `crates/dads-testing-core/src/plan_file.rs#verify_plan_freshness` and `crates/dads-testing-core/src/plan_fingerprint.rs#compute_workspace_fingerprint`, proven by `crates/dads-testing-core/tests/shard_and_plan_file.rs#run_with_plan_file_reuses_plan_without_git_diff_and_supports_sharding`.
- INV-TESTING-40: Semantic edits to ambient `.d.ts`/`.d.mts`/`.d.cts` declaration files widen `reachability` `typecheck` tasks across projects without widening runtime `test` tasks, and static manifests inherit project-level `vitest.config.*` `setupFiles` and fail closed on dynamic `setupFiles` — enforced by `crates/dads-testing-core/src/plan/widening_fs.rs#widen_ambient_dts_typechecks` and `crates/dads-testing-core/src/discover_vitest.rs#hydrate_static_vitest_setup_files`, proven by `crates/dads-testing-core/tests/declarative_discover.rs#expand_manifest_produces_canonical_ir_preserving_file_narrowing_and_optional_deps`.
- INV-TESTING-41: `dad-test doctor` statically proves Vitest tier target parity, Vitest ↔ `fileNarrowing` alignment, complete test-file ownership, non-overlapping narrowed targets, and zero whole-workspace uncertainties — enforced by `crates/dads-testing-core/src/doctor.rs#build_doctor` and `src/commands/doctor.ts#doctorCommand`, proven by `crates/dads-testing-core/tests/doctor.rs` and `src/commands/doctor.test.ts`.

## The native boundary

- INV-TESTING-8: The plan and run wire contract is protocol schemaVersion 1, and a published key is never renamed, dropped, or re-valued while that version holds — enforced by `crates/dads-testing-core/src/protocol.rs` (`PROTOCOL_SCHEMA_VERSION` and its serde attributes), proven by `crates/dads-testing-core/tests/wire_golden.rs#the_live_plan_response_still_carries_every_key_the_golden_records` and `#the_protocol_schema_version_never_falls_below_the_recorded_floor`.
- INV-TESTING-9: Each `plan` or `run` operation makes exactly one request to the native process, and an option the caller did not set is omitted from that request rather than sent as null — enforced by `src/testing-api.ts#invokeNativeTestingEngine` and `#toNativeRequest`, proven by `src/cli.test.ts` "writes the versioned envelope and sends one plan request".
- INV-TESTING-10: A field the engine did not report means the engine is older than this facade, not that the fact does not hold: task ownership and causes stay optional, and an issue without a declared `severity` or `scope` is classified from its code — enforced by `src/plan-issues.ts#issueSeverity` and `#issueScope`, proven by `src/plan-issues.test.ts` "derives severity from the issue code for an older engine" and "derives scope from the issue code for an older engine", and `src/testing-api.test.ts` "reads task ownership, causes, and located issues from a newer engine".
- INV-TESTING-11: The native engine is the optional package matching the host platform and architecture; an unsupported target or a missing package is an error naming that package, and an explicit `nativeBinary` or `DADS_TEST_NATIVE_BINARY` must point at an existing file — enforced by `src/native-platform.ts#resolveNativeTestingBinary`, `#nativePackageDefinitionForPlatform`, and `#requireExistingDevelopmentBinary`, proven by `src/native-platform.test.ts` "maps every supported platform tuple to one optional package", "reports a missing optional package precisely", and "accepts an existing development binary without spawning it".
- INV-TESTING-33: A development binary replaces the platform package rather than backing it up — an explicit `nativeBinary`, then `DADS_TEST_NATIVE_BINARY`, are each read before any package lookup runs — and every resolution names the source that supplied the path, so a failure says which input was wrong — enforced by `src/native-platform.ts#resolveNativeTestingBinary`, `#developmentBinaryFor`, and `#requireExistingDevelopmentBinary`, proven by `src/native-platform.test.ts` "uses DADS_TEST_NATIVE_BINARY in place of a missing platform package", "reads an explicit nativeBinary before the variable", and "names the source that supplied a path with no file behind it".
- INV-TESTING-28: A caller only ever receives a result the engine produced for the operation it asked about: a response whose `schemaVersion` is not the protocol version, a non-ok envelope, an envelope with no result, a result for a different operation, a `run` result without run details, output that is not JSON, and JSON that is not the envelope are each an error naming what was wrong — enforced by `src/testing-api.ts#requireResultFor`, `#isNativeResponse`, `#runNativeProcess`, and `#runTesting`, proven by `src/testing-api-refusals.test.ts` "refuses a native response whose schemaVersion is not the protocol version", "refuses a non-ok envelope, reporting the engine's own error message", "refuses an ok envelope that carries no result at all", "refuses a result for an operation the caller did not request", "refuses a run result that carries a plan but no run details", "refuses a response that is not JSON, quoting what the engine wrote to stderr", and "refuses JSON that is not the native envelope".
- INV-TESTING-31: The engine refuses a request it cannot honor before it reads a manifest or resolves a scope — a `schemaVersion` other than 1, a `--head` with no `--base`, and `--all` combined with `--base` or `--head` — and every refusal leaves through the protocol as an `ok: false` response rather than a panic — enforced by `crates/dads-testing-core/src/execute.rs#execute`, proven by `crates/dads-testing-core/tests/request_refusals.rs#an_unsupported_request_schema_version_is_refused`, `#a_head_without_a_base_is_refused`, and `#all_combined_with_a_base_or_a_head_is_refused`.
- INV-TESTING-32: The `dad-test` binary appends the snapshot store's issues after the core's own, so an issue index a decision cites still names the issue the planner meant — enforced by `crates/dads-testing-cli/src/main.rs`, proven by `crates/dads-testing-cli/tests/plan_issue_order.rs#store_issues_are_appended_after_the_core_issues_a_decision_cites`.

## Nx testing integration

The Nx entry point holds two surfaces over one boundary: a one-way standalone importer
(`importNxTestingWorkspace`) that turns an Nx workspace into a Dads-owned
manifest, and a live adapter (`planNativeNxTesting`, `runNativeNxTesting`) that
builds a manifest from the current Nx graph on every call. Neither puts Nx on the
execution path of `@dads-framework/testing`.

### The standalone import

- INV-TESTING-IMPORT-NX-1: An import reads only a workspace with no uncommitted or untracked changes whose HEAD is exactly the full Git object ID the caller approved, and that check runs before Nx is asked anything — enforced by `src/nx/nx-workspace-reader.ts#requireCleanCommittedWorkspace` and `#readApprovedSha`, proven by `src/nx/import-nx.test.ts` "refuses a dirty source workspace before querying Nx" and "refuses a caller snapshot that differs from clean HEAD before querying Nx".
- INV-TESTING-IMPORT-NX-2: Only a fully materialized `nx:run-commands` target becomes a Dads task; a continuous target, an Nx-owned executor, a target carrying execution-affecting Nx fields, and a target with no resolved command are each left behind with a classification and a reason in the report — enforced by `src/nx/nx-target-conversion.ts#convertTarget`, `#unsupportedTargetReason`, and `#foreignExecutorReason`, proven by `src/nx/import-nx.test.ts` "converts only a resolved argv-safe run-commands task and audits every seam" (targets `watch` and `lint`).

### The live adapter

- INV-TESTING-IMPORT-NX-10: Discovery, planning, and execution are bound to one exact Git-visible working tree: the tree is fingerprinted before discovery and re-checked after planning and after execution, and any change invalidates the result rather than reporting it — enforced by `src/nx/nx-native-workspace.ts#requireUnchangedSource` and `src/nx/nx-native-scratch.ts#nativeNxSourceIdentity`, proven by `src/nx/nx-native-workspace.test.ts` "cleans scratch after graph failure and rejects source mutation before native" and "rejects a workspace changed by the native run".
- INV-TESTING-IMPORT-NX-11: Temporary manifests and raw graphs are written only into a directory that is physically inside the workspace and confirmed ignored by Git, and that directory is removed even when the call fails — enforced by `src/nx/nx-native-scratch.ts#createNativeNxScratch` and `src/nx/nx-native-workspace.ts#withNativeNxManifest`, proven by `src/nx/nx-native-workspace.test.ts` "requires the scratch directory itself to be ignored" and "cleans scratch after graph failure and rejects source mutation before native".
- INV-TESTING-IMPORT-NX-12: The task inventory is rebuilt from the current Nx graph on every call, so a newly added target is never omitted by a frozen manifest — enforced by `src/nx/nx-native-workspace.ts#discoverManifest` and `src/nx/nx-native-model.ts#buildNativeNxManifest`, proven by `src/nx/nx-native-workspace.test.ts` "refreshes target inventory on every call" and `src/nx/nx-native-model.test.ts` "discovers newly added targets on each build and honors exact scope overrides".
- INV-TESTING-IMPORT-NX-13: Nx keeps ownership of execution: a registered task runs the installed Nx CLI as `run --project=<project> --target=<target>`, every excluded target — continuous, or outside the requested verification scope — is recorded with its reason in the coverage report, and the generated `workspace.fullFallback.taskIds` names every registered task — enforced by `src/nx/nx-native-model.ts#registerSelectedTargets`, `#buildTaskEntry`, and `#buildNativeNxManifest`, proven by `src/nx/nx-native-model.test.ts` "preserves native argv and configuration ownership while auditing exclusions" and `src/nx/nx-native-workspace.test.ts` "discovers the graph through Nx and sends an in-workspace manifest to Dads".
- INV-TESTING-IMPORT-NX-14: An input the adapter cannot locate as a file makes the task run on every invocation rather than narrowing its scope, and nothing else does. The complete list of reasons: an unreadable `nx.json`; a `runtime` or `env` input, or any other input object that names neither a fileset nor a JSON file; a named input that does not resolve, or resolves cyclically; malformed workspace or project `namedInputs`, malformed `targetDefaults`, malformed target `inputs`, malformed `configurations`, or malformed `dependsOn`; an input path that is absolute, escapes the workspace, or resolves to the workspace root; a project dependency the graph does not name; a prerequisite whose project the graph does not name; and a visited project rooted at `.`, which owns every path and so cannot be scoped at all. - INV-TESTING-IMPORT-NX-15: A resolvable file scope is widened, never narrowed: a glob contributes its literal prefix, an exclusion pattern subtracts nothing, and the scope always contains the workspace policy files plus every transitively reachable project dependency root — enforced by `src/nx/nx-native-input-expansion.ts#expandFileInput` and `#literalPrefix`, and `src/nx/nx-native-inputs.ts#visitProject`, proven by `src/nx/nx-native-inputs.test.ts` "widens glob prefixes and ignores exclusions instead of subtracting inputs", "retains global policy and cross-project extglob prefixes when a root project owns globals", and "expands named inputs using each dependency project's overrides", and `src/nx/nx-native-model.test.ts` "supports project cycles supported by core while retaining both dependency roots".
