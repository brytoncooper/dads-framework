# Nx testing integration invariants

The package holds two surfaces over one boundary: a one-way standalone importer
(`importNxTestingWorkspace`) that turns an Nx workspace into a Dads-owned
manifest, and a live adapter (`planNativeNxTesting`, `runNativeNxTesting`) that
builds a manifest from the current Nx graph on every call. Neither puts Nx on the
execution path of `@dads-framework/testing`.

## The standalone import

- INV-TESTING-IMPORT-NX-1: An import reads only a workspace with no uncommitted or untracked changes whose HEAD is exactly the full Git object ID the caller approved, and that check runs before Nx is asked anything — enforced by `src/nx-workspace-reader.ts#requireCleanCommittedWorkspace` and `#readApprovedSha`, proven by `src/import-nx.test.ts` "refuses a dirty source workspace before querying Nx" and "refuses a caller snapshot that differs from clean HEAD before querying Nx".
- INV-TESTING-IMPORT-NX-2: Only a fully materialized `nx:run-commands` target becomes a Dads task; a continuous target, an Nx-owned executor, a target carrying execution-affecting Nx fields, and a target with no resolved command are each left behind with a classification and a reason in the report — enforced by `src/nx-target-conversion.ts#convertTarget`, `#unsupportedTargetReason`, and `#foreignExecutorReason`, proven by `src/import-nx.test.ts` "converts only a resolved argv-safe run-commands task and audits every seam" (targets `watch` and `lint`).
- INV-TESTING-IMPORT-NX-3: A command a shell would have to interpret never becomes a standalone task; it stays in the report as opaque — enforced by `src/nx-target-conversion.ts#parseStandaloneArgv`, proven by `src/import-nx.test.ts` "converts only a resolved argv-safe run-commands task and audits every seam" (target `shell`).
- INV-TESTING-IMPORT-NX-4: A Vite or Vitest command whose config imports `nxViteTsPaths`, or whose config this importer cannot read, is classified as needing a native adapter rather than converted, because being wrong here ships a task that fails only outside Nx — enforced by `src/nx-target-conversion.ts#hasNxViteTsPaths`, proven by `src/import-nx.test.ts` "converts only a resolved argv-safe run-commands task and audits every seam" (target `vite`).
- INV-TESTING-IMPORT-NX-5: Every Nx graph edge whose `source` agrees with its containing dependency key becomes a Dads project fallback dependency from source to target, so the imported manifest never widens less than the Nx graph implies — enforced by `src/nx-graph-fallback.ts#parseNxGraphFallbackDependencies` and `#readEdgeTarget`, proven by `src/import-nx.test.ts` "converts only a resolved argv-safe run-commands task and audits every seam".
- INV-TESTING-IMPORT-NX-6: The generated manifest and report are ordered by identity — projects and tasks by Dads id, task audits by project and target — and every Dads id is a reversible encoding of the Nx name, so an unchanged workspace imports to the same document — enforced by `src/import-nx-workspace.ts#buildManifest` and `#buildReport`, and `src/dads-identifier.ts#dadsIdentifier`, proven by `src/import-nx.test.ts` "converts only a resolved argv-safe run-commands task and audits every seam".
- INV-TESTING-IMPORT-NX-7: The manifest and report the import returns are exactly the two files it wrote at the paths it reports, written through unique temporary siblings so no reader ever sees a half-written file, and no output is put in place until every one of them has been written — enforced by `src/import-nx-workspace.ts#writeImportOutputs` and `src/atomic-output.ts#writeOutputsAtomically`, proven by `src/import-nx.test.ts` "converts only a resolved argv-safe run-commands task and audits every seam", and `src/atomic-output.test.ts` "writes every output and leaves no temporary sibling behind" and "renames nothing and removes every temporary file when one write fails".
- INV-TESTING-IMPORT-NX-26: Two named paths cannot be replaced in one filesystem step, so the outputs are renamed in order and the guarantee stops where the filesystem does: a rename failure leaves the outputs before it replaced and the rest untouched, with no temporary file left behind, and the report's `manifestChecksum` is the digest of the manifest bytes so a torn pair does not read as a matching one — enforced by `src/atomic-output.ts#writeOutputsAtomically` and `src/import-nx-workspace.ts#importNxTestingWorkspace` (the checksum), proven by `src/atomic-output.test.ts` "replaces the outputs before a failed rename and nothing after it".
- INV-TESTING-IMPORT-NX-8: The Nx CLI both surfaces run is the one installed in the target workspace, resolved through that package's own `bin` entry, and never a path that resolves outside the installed package — enforced by `src/nx-installation.ts#resolveLocalNxCli`, `#resolveCliCandidate`, and `#validatePackagePath`, proven by `src/nx-installation.test.ts` "resolves the declared nx bin and accepts a symlinked package directory", "uses the legacy bin fallback only when bin is absent", and "refuses malformed or escaping explicit bin entries".
- INV-TESTING-IMPORT-NX-9: `nx.json` is read as JSONC — comments and trailing commas removed without altering string contents — and a file that is not valid after that is reported rather than partly read — enforced by `src/nx-jsonc.ts#parseNxConfiguration`, proven by `src/nx-installation.test.ts` "parses comments and trailing commas without changing strings" and "reports malformed JSONC".
- INV-TESTING-IMPORT-NX-17: An Nx graph shape this importer does not understand stops the import rather than producing a narrower fallback — graph output that is not an object, a missing `graph`, `graph.nodes` or `graph.dependencies`, a project with no object node or no edge array, an edge that is not an object or whose `source` disagrees with its containing key, an edge with no target, and a self dependency are each refused — enforced by `src/nx-graph-fallback.ts#readGraphBody`, `#readProjectEdges`, `#readEdgeTarget`, and `#projectDependencies`, proven by `src/nx-graph-fallback.test.ts` "refuses graph output that is not a JSON object", "refuses graph output with no top-level graph object", "refuses a graph missing either nodes or dependencies", "refuses a project the graph does not describe as an object node", "refuses a project whose declared edges are not an array", "refuses a dependency edge that is not an object", "refuses an edge whose source disagrees with its containing key", "refuses an edge that declares no target", and "refuses a self dependency strict v1 cannot represent".
- INV-TESTING-IMPORT-NX-18: A refused import is still evidence: whether Nx could not produce a graph at all or answered in a shape this importer does not understand, the report is written before the failure is raised, carries the one failure that stopped it and everything already read, and no `dads.testing.json` is written beside it — enforced by `src/import-nx-workspace.ts#readGraphOrReport`, `#resolveFallbackOrReport`, and `#writeUnsupportedGraphReport`, proven by `src/import-nx.test.ts` "leaves the unsupported-graph report behind when Nx cannot produce a graph" and "leaves the unsupported-graph report behind when the graph shape is not understood".
- INV-TESTING-IMPORT-NX-19: An import that converts no target writes only the report — a `null` `manifestChecksum` and a conversion failure naming why — because a strict v1 manifest requires at least one task — enforced by `src/import-nx-workspace.ts#writeImportOutputs` and `#noStandaloneReport`, proven by `src/import-nx.test.ts` "writes only the report when no target converts, because strict v1 needs one task".
- INV-TESTING-IMPORT-NX-20: The report's `manifestChecksum` is the SHA-256 of the exact bytes of the manifest that was written beside it, and those bytes are reproducible: equal data serializes to equal bytes with every object key sorted, so key order and spacing are part of the contract rather than a formatting preference — enforced by `src/json-values.ts#stableJson` and `src/import-nx-workspace.ts#importNxTestingWorkspace`, proven by `src/json-values.test.ts` "produces identical bytes for equal data written in different key orders", "sorts every nested object key, keeps array order, and ends with one newline", and "refuses to serialize an output value JSON cannot round-trip", and `src/import-nx.test.ts` "records the manifest checksum as the digest of the manifest file it wrote".
- INV-TESTING-IMPORT-NX-21: The inputs an import was taken over are recorded by content: every workspace lockfile and configuration file that exists plus each project's own `project.json` and `package.json` is hashed once and reported sorted by path, an absent file is skipped rather than recorded as empty, and any other read failure is raised — enforced by `src/import-digest.ts#digestInputs`, `#digestProjectInputs`, and `#digestOptionalFile`, proven by `src/import-digest.test.ts` "hashes bytes with SHA-256", "digests only the workspace files that exist, in the order the report lists them", "records no input for a workspace that declares none of them", "adds each project's own configuration once and returns the whole set sorted by path", and "raises a read failure that is not a missing file".
- INV-TESTING-IMPORT-NX-22: A converted task has nothing left to resolve and no way back to a shell or to Nx: an unresolved placeholder, a working directory that is absolute or escapes the source workspace, an unclosed quote, a shell escape, shell control syntax, an empty command, and any argument that would invoke Nx are each refused with the reason recorded in the audit — enforced by `src/nx-target-conversion.ts#resolveTemplate`, `#resolveCwd`, `#splitArgv`, `#scanCharacter`, `#parseStandaloneArgv`, and `#invokesNx`, proven by `src/nx-target-conversion.test.ts` "refuses a command that still contains an unresolved Nx placeholder", "refuses a working directory that escapes the source workspace", "refuses a working directory that is absolute after placeholder resolution", "refuses a command with an unclosed quote", "refuses a command that uses shell escapes", "refuses every form of shell control syntax", "refuses a command that would put Nx back on the execution path", and "refuses an empty command and a target with no resolved command at all".

## The live adapter

- INV-TESTING-IMPORT-NX-10: Discovery, planning, and execution are bound to one exact Git-visible working tree: the tree is fingerprinted before discovery and re-checked after planning and after execution, and any change invalidates the result rather than reporting it — enforced by `src/nx-native-workspace.ts#requireUnchangedSource` and `src/nx-native-scratch.ts#nativeNxSourceIdentity`, proven by `src/nx-native-workspace.test.ts` "cleans scratch after graph failure and rejects source mutation before native" and "rejects a workspace changed by the native run".
- INV-TESTING-IMPORT-NX-11: Temporary manifests and raw graphs are written only into a directory that is physically inside the workspace and confirmed ignored by Git, and that directory is removed even when the call fails — enforced by `src/nx-native-scratch.ts#createNativeNxScratch` and `src/nx-native-workspace.ts#withNativeNxManifest`, proven by `src/nx-native-workspace.test.ts` "requires the scratch directory itself to be ignored" and "cleans scratch after graph failure and rejects source mutation before native".
- INV-TESTING-IMPORT-NX-12: The task inventory is rebuilt from the current Nx graph on every call, so a newly added target is never omitted by a frozen manifest — enforced by `src/nx-native-workspace.ts#discoverManifest` and `src/nx-native-model.ts#buildNativeNxManifest`, proven by `src/nx-native-workspace.test.ts` "refreshes target inventory on every call" and `src/nx-native-model.test.ts` "discovers newly added targets on each build and honors exact scope overrides".
- INV-TESTING-IMPORT-NX-13: Nx keeps ownership of execution: a registered task runs the installed Nx CLI as `run --project=<project> --target=<target>`, every excluded target — continuous, or outside the requested verification scope — is recorded with its reason in the coverage report, and the generated `workspace.fullFallback.taskIds` names every registered task — enforced by `src/nx-native-model.ts#registerTarget` and `#buildNativeNxManifest`, proven by `src/nx-native-model.test.ts` "preserves native argv and configuration ownership while auditing exclusions" and `src/nx-native-workspace.test.ts` "discovers the graph through Nx and sends an in-workspace manifest to Dads".
- INV-TESTING-IMPORT-NX-14: An input the adapter cannot locate as a file makes the task run on every invocation rather than narrowing its scope, and nothing else does. The complete list of reasons: an unreadable `nx.json`; a `runtime` or `env` input, or any other input object that names neither a fileset nor a JSON file; a named input that does not resolve, or resolves cyclically; malformed workspace or project `namedInputs`, malformed `targetDefaults`, malformed target `inputs`, malformed `configurations`, or malformed `dependsOn`; an input path that is absolute, escapes the workspace, or resolves to the workspace root; a project dependency the graph does not name; a prerequisite whose project the graph does not name; and a visited project rooted at `.`, which owns every path and so cannot be scoped at all. The presence of plugins, `targetDefaults`, `dependsOn`, configurations, or external dependencies is not a reason — enforced by `src/nx-native-inputs.ts#inputScope`, `#visitProject`, `#addNamedPrerequisite`, and `src/nx-native-input-expansion.ts#expandInput` and `#expandObjectInput`, proven by `src/nx-native-inputs.test.ts` "uses always for unresolved, runtime and environment inputs", "falls back for cyclic definitions and invalid configuration boundaries", and "keeps a workspace-root project and an unresolved dependency at always", and `src/nx-native-plugin-workspace.test.ts` "keeps a runtime named input on always and counts exactly those tasks".
- INV-TESTING-IMPORT-NX-15: A resolvable file scope is widened, never narrowed: a glob contributes its literal prefix, an exclusion pattern subtracts nothing, and the scope always contains the workspace policy files plus every transitively reachable project dependency root — enforced by `src/nx-native-input-expansion.ts#expandFileInput` and `#literalPrefix`, and `src/nx-native-inputs.ts#visitProject`, proven by `src/nx-native-inputs.test.ts` "widens glob prefixes and ignores exclusions instead of subtracting inputs", "retains global policy and cross-project extglob prefixes when a root project owns globals", and "expands named inputs using each dependency project's overrides", and `src/nx-native-model.test.ts` "supports project cycles supported by core while retaining both dependency roots".
- INV-TESTING-IMPORT-NX-16: An Nx graph that is malformed or whose identities are ambiguous is refused rather than partly modeled: a missing node or dependency array, an edge whose source or target does not resolve, a project whose declared name differs from its key, two projects sharing a root, an escaping project root, and an external node colliding with a project each stop the build, and an external dependency never becomes a Dads project — enforced by `src/nx-native-graph.ts#readNativeProjects`, `#readNativeProject`, `#readNativeEdgeTarget`, `#validateDependencySources`, `#readExternalNames`, and `#projectRoot`, proven by `src/nx-native-model.test.ts` "rejects malformed graph structure and ambiguous project identities" and "keeps external dependency inputs conservative without inventing projects".
- INV-TESTING-IMPORT-NX-23: A live Nx graph describes the checkout and never a different historical head: `--all` combined with `--base` or `--head` is refused, `--head` without `--base` is refused, and a `--head` that is not the clean checked-out HEAD — a different revision, or a dirty working tree — is refused before any graph is collected — enforced by `src/nx-native-scope.ts#requireNativeNxScope`, proven by `src/nx-native-scope.test.ts` "refuses --all combined with --base or --head", "refuses --head without --base", "refuses a --head that names a revision other than the checked-out HEAD", "refuses a --head at HEAD when the working tree is dirty", "accepts a working-tree scope and an --all scope without a revision", and "accepts a --head that is the clean checked-out HEAD".
- INV-TESTING-IMPORT-NX-24: A discovery that registers no verification target is refused rather than sent to Dads as an empty manifest, whether the graph declares no targets, only continuous ones, only targets outside the verification families, or none the caller named — enforced by `src/nx-native-model.ts#buildNativeNxManifest`, proven by `src/nx-native-model.test.ts` "refuses a graph that registers no verification target at all".
- INV-TESTING-IMPORT-NX-25: A run through the live adapter returns the Nx coverage, the plan, and the execution results of one still working tree, and removes its scratch directory on the way out — enforced by `src/nx-native-workspace.ts#runNativeNxTesting` and `#withNativeNxManifest`, proven by `src/nx-native-workspace.test.ts` "returns the Nx coverage, the plan, and the run results of a still workspace".
- INV-TESTING-IMPORT-NX-27: A plugin-inferred target is scoped from what Nx declares, not refused for being plugin-inferred: the scope is the project's root, every transitively reachable dependency root, the workspace policy files, and every file input expanded from the target's own `inputs` — or, when it declares none, from the `targetDefaults` entries keyed by its name, its executor, or a wildcard — together with every configuration's inputs, since a configuration matters only when it adds an input the default does not — enforced by `src/nx-native-inputs.ts#inputScope`, `#expandDeclaredInputs`, `#targetDefaultInputs`, and `#expandConfigurationInputs`, proven by `src/nx-native-inputs.test.ts` "keeps plugins, targetDefaults, prerequisites and configurations out of the reasons", "takes targetDefaults inputs only for a target that declares none of its own", and "unions the inputs every configuration adds to the default ones", and `src/nx-native-plugin-workspace.test.ts` "narrows a plugin-inferred workspace to the changed project and its dependents" and "expands targetDefaults and named inputs into the paths they name".
- INV-TESTING-IMPORT-NX-28: A `dependsOn` prerequisite is followed to the projects Nx names for it rather than assumed to be inside the dependency graph — Nx normalizes `^build` into an explicit project list, and in a real workspace most of those projects are not in the declaring project's import graph — so each prerequisite's project root, its own dependency roots, and its own prerequisites join the scope, and a prerequisite naming a project the graph does not carry selects `always` — enforced by `src/nx-native-inputs.ts#visitTarget`, `#collectPrerequisites`, `#addPrerequisite`, `#addNamedPrerequisites`, and `#addDependencyPrerequisites`, proven by `src/nx-native-inputs.test.ts` "follows a prerequisite to the exact projects Nx names for it" and `src/nx-native-plugin-workspace.test.ts` "follows a prerequisite into a project the dependency graph does not reach".
- INV-TESTING-IMPORT-NX-29: A change no declared project owns still selects every task, because the workspace policy paths — the lockfiles, `package.json`, `nx.json`, and the root `tsconfig` files — are in every scope, and any other unowned path reaches the engine's complete fallback. Where the Nx graph declares a project rooted at `.`, that project owns every otherwise-unowned path and the fallback cannot fire, so a root-level file is in scope only when Nx's own input model names it; the adapter states that assumption in every registered task's reason instead of implying a precision it does not have — enforced by `src/nx-native-inputs.ts#inputScope` (its `globalPolicyPaths` and `scopeReason`), proven by `src/nx-native-plugin-workspace.test.ts` "sends an unowned root configuration change to the complete fallback".
