# Path alias invariants

- INV-PATH-ALIASES-1: Aliases come from the one tsconfig the caller named, whether that config declares `compilerOptions.paths` itself or inherits them through its `extends` chain; the nearest config in that chain that declares them owns them, and its targets resolve against that config's `baseUrl`, the nearest `baseUrl` after it in the chain, or its own directory — enforced by `src/alias-resolver.ts#createAliasResolver` and `src/tsconfig-chain.ts#readTsconfigChain`, `#readDeclaredAliases`, and `#baseUrlFrom`, proven by `src/alias-resolvers.test.ts` "obeys resolves-exact-alias", "obeys resolves-package-extends", "resolves an alias declared by the tsconfig it was named", and "resolves alias targets from the baseUrl the declaring config sets".
- INV-PATH-ALIASES-2: A resolved specifier is an absolute path to a file that exists: the alias target is probed as a file, then as a package directory, then with each supported extension, then as `index.<extension>` inside it, and a specifier written with an explicit extension falls back to the matching source file — enforced by `src/alias-resolver.ts#resolveCandidate`, `#findSupportedFile`, and `#explicitExtensionSource`, proven by `src/alias-resolvers.test.ts` "obeys resolves-wildcard-alias", "obeys resolves-extensionless-index", "obeys resolves-explicit-extension", and "obeys strips-query-suffix".
- INV-PATH-ALIASES-3: A specifier this package does not own answers `null` and stays the caller's to resolve — a bare specifier, an alias whose target names no existing file, and any absolute path — so the resolver never claims a module it cannot prove, and a specifier is honored because `paths` declares it rather than because a file sits under `baseUrl` — enforced by `src/alias-resolver.ts#shouldDefer`, `#matchAlias`, and `#resolveSpecifier`, proven by `src/alias-resolvers.test.ts` "obeys defers-bare-specifier", "obeys defers-unmatched-alias", and "obeys defers-absolute-specifier".
- INV-PATH-ALIASES-4: When an alias target is a package directory, the entry point is the first of `exports`, `module`, and `main` that names an existing file, for every manifest shape and for no manifest at all; a manifest that cannot be read is no manifest, so resolution falls through to the extension and index probes — enforced by `src/alias-resolver.ts#packageEntryFile`, `#readPackageManifest`, and `#packageEntry`, proven by `src/alias-resolvers.test.ts` "obeys resolves-package-entry", "obeys resolves-package-without-manifest", and "obeys ignores-unparsable-manifest".
- INV-PATH-ALIASES-5: Every configuration the package cannot honor fails while the resolver is being built rather than resolving less at run time: a blank `tsconfig`, a tsconfig that is not a readable file, a config in the `extends` chain it cannot read or parse, a tsconfig that neither declares nor inherits `paths`, an alias whose target list does not hold exactly one usable target, a wildcard count the target does not match, an `extends` that is neither a string nor a string array, a relative or package `extends` that resolves to nothing, and an `extends` chain that revisits a config — enforced by `src/alias-resolver.ts#requireTsconfigOption`, `#createAliasResolver`, and `#parseAliasMapping`, and `src/tsconfig-chain.ts#requireTsconfigFile`, `#readTsconfigFile`, `#readExtends`, `#resolveExtendsPath`, and `#readTsconfigChain`, proven by `src/alias-resolvers.test.ts` "obeys refuses-blank-tsconfig", "obeys refuses-missing-tsconfig", "obeys refuses-directory-tsconfig", "obeys refuses-unparsable-config", "obeys refuses-unparsable-extended-config", "obeys refuses-config-without-paths", "obeys refuses-alias-without-one-target", "obeys refuses-mismatched-wildcards", "obeys refuses-extends-shape", "obeys refuses-unresolvable-relative-extends", "obeys refuses-unresolvable-package-extends", and "obeys refuses-circular-extends".
- INV-PATH-ALIASES-6: The package reads the tsconfig dialect itself — comments, trailing commas, and strings that contain either — so resolving an alias never loads the TypeScript compiler and no compiler version can take the resolver away from an adopter; text it cannot parse names the file and the line and column it stopped at — enforced by `src/json-with-comments.ts#parseJsonWithComments` and `src/tsconfig-chain.ts#readTsconfigFile`, proven by `src/json-with-comments.test.ts` "reads a comment in every position a tsconfig can put one", "reads a trailing comma in an object and in an array", "keeps comment markers, quotes, and escapes inside strings", and "names the line and column it stopped at".
- INV-PATH-ALIASES-7: Every file question a resolver asks goes through the port — is this a file, what text does it hold, where does this package resolve to — so the resolver reaches no disk of its own and a second provider is possible at all — enforced by `src/alias-file-system.ts#AliasFileSystem` and `src/alias-resolver.ts#createAliasResolver`, proven by `src/alias-resolvers.test.ts` "answers no for a directory and for an unreadable path", "answers nothing for a package that is not installed", "refuses to read a path it does not hold, naming the path", and "finds a package by the node_modules walk, and answers nothing above the root".
- INV-PATH-ALIASES-8: Every provider of that port is held to one suite that a second implementation actually runs, and the suite reports a provider that answers wrongly rather than throwing at the first law it breaks — enforced by `src/alias-resolver-conformance.ts#runAliasResolverConformance` and `#aliasResolverConformanceLaws`, `src/alias-resolver-conformance-cases.ts#aliasResolutionCases`, `#aliasRefusalCases`, and `src/in-memory-file-system.ts#inMemoryFileSystem`, proven by `src/alias-resolvers.test.ts` "obeys builds-a-resolver", "breaks no law outside the ones this suite names", and "reports a file system whose isFile says yes to everything".
