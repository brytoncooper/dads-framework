Permissions

The last permissions system you'll ever need.

Write who can see what in plain TypeScript. It runs inside your own Postgres or SQLite database — simple to learn in 5 minutes, fast across millions of rows.

  • Uses the tables you already have Point Dad at your existing org_id or owner_id columns. No duplicate data, no syncing bugs, and revoking access takes effect instantly.
  • Fast at any scale Half-millisecond permission checks and instant filtered lists at scale — with no extra permissions database to run.
  • Proved correct, zero lock-in Mathematically verified for correctness, testable in milliseconds without Docker, and easy to move to or from SpiceDB if you ever need to. See the benchmarks & proof →
domains/tasks/access/index.ts 
import { actor, anyOf, compileAccess, resource } from "@dads-framework/access";

export const user = actor("user");

export const workspace = resource("workspace", {
  roles: { admin: user, member: user },
  can: ({ admin, member }) => ({
    manage: admin,
    view: [admin, member],
  }),
  children: {
    task: {
      inherit: "all",
      roles: { assignee: user, blocked: user },
      can: ({ assignee, blocked, parent }) => ({
        edit: anyOf(assignee, parent.manage).unless(blocked),
      }),
    },
    billing: {
      inherit: ["manage"],
      roles: { accountant: user },
      can: ({ accountant }) => ({ view: accountant }),
    },
  },
});

export const task = workspace.task;
export const model = compileAccess([workspace]);
import { fromParam, patchRoute, requires } from "@dads-framework/http";
import { task } from "../access/index.js";

export const updateTask = patchRoute({
  route: { method: "PATCH", template: "/tasks/:taskId" },
  summary: "Update a task",
  access: requires(task.can.edit, fromParam("taskId")),
  rateLimit: { perMinute: 60 },
  params: taskParams,
  body: updateTaskBody,
  response: taskResponse,
  handler: ({ params, body, subject }) =>
    // Rechecks access and writes in one PostgreSQL transaction.
    writeWithPermission(
      { subject, permission: task.can.edit, resourceId: params.taskId },
      (tx) => tasksStore.update(tx, params.taskId, body),
    ),
});
import { entityIdSchema } from "@dads-framework/core/contract";
import { workspaceId } from "../../../libraries/app-runtime/index.js";
import { z } from "zod";

// Owns the wire shapes for tasks: validation, OpenAPI 3.1, and clients.
export const taskId = entityIdSchema("TaskId", "Task id");
export const taskParams = z.strictObject({ taskId });

export const updateTaskBody = z.strictObject({
  title: z.string().trim().min(1).max(200),
});

export const taskResponse = z.object({
  id: taskId,
  workspaceId,
  title: z.string(),
});
import { sendToApi } from "@dads-framework/client";
import { defineRoute } from "@dads-framework/core/contract";
import { taskResponse, updateTaskBody } from "../contract/wire.js";

const updateTaskRoute = defineRoute(
  "PATCH",
  "/tasks/:taskId",
  (id: string) => `/tasks/${encodeURIComponent(id)}`,
);

// Works in React, Next.js, Vue, Svelte, or Node.
export function updateTask(taskId: string, title: string) {
  return sendToApi({
    route: updateTaskRoute.bind(taskId),
    body: { schema: updateTaskBody, value: { title } },
    returns: taskResponse,
  });
}

Multiple API servers

Keep public and admin APIs separate.

Share your business logic, never your endpoints. Your customer server and internal admin server only load the routes you give them.

  • Customer API Only loads routes meant for end users, protected by your permission rules.
  • Staff API Only loads internal admin tools. Customer routes don't even exist on it.

Automated CI checks

Catch mistakes before code review.

Whether a teammate or an AI agent opens the PR, Dad automatically checks folder rules, strict types, and permission tests.

  • Clean folder boundaries Stops one feature from reaching into another feature's private files or database tables.
  • No sneaky shortcuts Blocks any, unsafe casts, unprotected routes, and untested permission rules in CI.
  • Use only what you need Already have an app? Drop in just the permissions or routes package — no rewrite required.
