Relationship permissions

Permissions that live inside your database transactions.

Write who can access what in plain TypeScript. Remove someone from a workspace and every task, note, and file inside it locks down in the same PostgreSQL or SQLite transaction.

  • No scattered if (user.role) checks Declare top-down children and explicit inherit rules once. Routes will not compile without an access rule, and unauthorized calls return 404 before parsing input.
  • No brittle SQL RLS policy strings Typed TypeScript models with autocomplete, in-memory tests, and zero hand-written Postgres or SQLite policy SQL.
  • No extra auth database or ORM lock-in Runs directly on plain pg.Pool, Drizzle, or SQLite with sub-millisecond checks. Already on SpiceDB? Import .zed schemas and cut over live tuples into PostgreSQL with parity checks.
domains/tasks/access/index.ts 
import { actor, anyOf, compileAccess, resource } from "@dads-framework/access";

export const user = actor("user");

export const workspace = resource("workspace", {
  roles: { admin: user, member: user },
  can: ({ admin, member }) => ({
    manage: admin,
    view: [admin, member],
  }),
  children: {
    task: {
      inherit: "all",
      roles: { assignee: user, blocked: user },
      can: ({ assignee, blocked, parent }) => ({
        edit: anyOf(assignee, parent.manage).unless(blocked),
      }),
    },
    billing: {
      inherit: ["manage"],
      roles: { accountant: user },
      can: ({ accountant }) => ({ view: accountant }),
    },
  },
});

export const task = workspace.task;
export const model = compileAccess([workspace]);
import { fromParam, patchRoute, requires } from "@dads-framework/http";
import { task } from "../access/index.js";

export const updateTask = patchRoute({
  route: { method: "PATCH", template: "/tasks/:taskId" },
  summary: "Update a task",
  access: requires(task.can.edit, fromParam("taskId")),
  rateLimit: { perMinute: 60 },
  params: taskParams,
  body: updateTaskBody,
  response: taskResponse,
  handler: ({ params, body, subject }) =>
    // Rechecks access and writes in one PostgreSQL transaction.
    writeWithPermission(
      { subject, permission: task.can.edit, resourceId: params.taskId },
      (tx) => tasksStore.update(tx, params.taskId, body),
    ),
});
import { entityIdSchema } from "@dads-framework/contract";
import { workspaceId } from "../../../libraries/app-runtime/index.js";
import { z } from "zod";

// Owns the wire shapes for tasks: validation, OpenAPI 3.1, and clients.
export const taskId = entityIdSchema("TaskId", "Task id");
export const taskParams = z.strictObject({ taskId });

export const updateTaskBody = z.strictObject({
  title: z.string().trim().min(1).max(200),
});

export const taskResponse = z.object({
  id: taskId,
  workspaceId,
  title: z.string(),
});
import { sendToApi } from "@dads-framework/client-request-transport";
import { defineRoute } from "@dads-framework/contract";
import { taskResponse, updateTaskBody } from "../contract/wire.js";

const updateTaskRoute = defineRoute(
  "PATCH",
  "/tasks/:taskId",
  (id: string) => `/tasks/${encodeURIComponent(id)}`,
);

// Works in React, Next.js, Vue, Svelte, or Node.
export function updateTask(taskId: string, title: string) {
  return sendToApi({
    route: updateTaskRoute.bind(taskId),
    body: { schema: updateTaskBody, value: { title } },
    returns: taskResponse,
  });
}

Multiple API servers

Separate entrypoints, shared domains.

Pick which routes and background jobs each server exposes with composeApi. Your customer and staff APIs share business code, never each other's endpoints.

  • Customer API serves product routes Mounts sign-in, workspaces, notes, and background workers behind permission checks.
  • Staff API never registers them Mounts internal admin and audit routes only. Customer routes aren't hidden behind a flag; they don't exist on the server.

Automated CI checks

Rules checked by tools, not reviewer memory.

Whether a teammate or a coding agent opens the PR, Dads verifies folder boundaries, strict types, and access denial tests automatically.

  • Domain boundaries in CI npx dad check boundaries stops features from importing another feature's database tables or internal files.
  • Automated code quality gate npx dad doctor --gate catches any, unsafe casts, routes without access rules, and missing denial tests.
  • Adopt one package at a time Already have an app? Install @dads-framework/postgres-access, sqlite-access, or http standalone in any TypeScript backend.
