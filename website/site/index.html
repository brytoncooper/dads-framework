Follow a request.

GET /tenants/:tenantId/notes ↗

  1. Validate the input

    The route declares the tenant ID, pagination parameters, and response item. Those schemas also describe the endpoint in OpenAPI.

  2. Check the relationship

    A session identifies the caller. The tenant’s view permission decides whether that caller can read notes in this workspace.

  3. Scope the query

    The handler filters by the authorized tenant ID before it counts or returns rows. Another workspace’s notes stay out of the result.

When you need a second API.

The customer API exposes notes. The staff API exposes audit exports. Each entrypoint chooses its routes and can share domain services.

See how API composition works

Customer API

apps/customer/app.ts ↗ 
  return composeApi("customer", {
    services: [provider, starterAccess],
    routes: [
      tenantsPlugin,
      tenantPermissionsPlugin,
      notesPlugin,
      // dad:add domains
    ],
    jobs: [notesAttachmentWorker],
  });
